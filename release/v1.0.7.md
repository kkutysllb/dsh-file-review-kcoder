# dsh-file-review-kcoder 1.0.7

> QiLin（麒麟）双通道适配 + system prompt section 泄漏修复。

## 变更

- **QiLin 双通道 manifest**：`package.json` 新增 `qilin` 键，与 `dsh`
  键指向同一份 `cordis.patch.yml` 与同一份 client 交付物。QiLin
  （dsh 0.1.6-alpha.2 合并后）的插件管理器只认原生键
  `qilin.bundle.patch`（缺失报「没有声明组合包」），DSH 宿主仍读
  `dsh.*`；两通道行为完全一致。client 注入表在 QiLin 通道把
  dsh-coding-sidebar 写为 `@qilin/coding-sidebar`（同一工作台的
  QiLin 内置名）。
- **exports 新增 `./cordis.patch.yml`**：bundle.patch 经裸包名从包内
  解析所需。
- **README**：QiLin 通道安装章节与注意事项——必须经 `qilin plugin add`
  装进 profile（profile 私有 node_modules 是裸包名解析第一跳，共享
  目录是安装保留区）、引擎版本 3.0.0+（运行）/ 3.0.2+（插件管理）、
  alpha.2 起运行时依赖解析模式、注入表差异。
- **fix：systemPrompt.section 泄漏**：`systemPrompt.section()` 的
  disposer 挂在服务自身 ctx 的 effect 上，不会随插件 fiber 回收；
  现由插件 `ctx.effect` 收集，停用/卸载（HMR）时才能撤销该 section
  （否则 system prompt 里残留 `ui:file-review-references` 段落）。
- 构建产物同步重建（`lib/client.js` 仅 CSS module 键序重排，无行为
  变化）。

## 验证

typecheck exit 0；build 幂等复建无漂移；smoke 45/45 +
render 13/13；镜像对账（sync-to-dsh-plugins --check）通过。

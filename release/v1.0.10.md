# dsh-file-review-kcoder 1.0.10

> 修 web boot 失败：文件动作子槽改用自有命名空间键
> `dsh-file-review-kcoder.file.actions`，不再认领 upstream 的
> `deliverables.file.actions`；客户端 inject 清单改列 0.1.7 真实图行。

## 变更

- **修 web boot 失败——动作子槽改用自有键**：0.1.7-alpha.1 起 upstream 原生交付卡把
  `deliverables.file.actions` 声明为自己的子键（fork
  `packages/client/ui-deliverables/src/client/index.ts:83`），而一个子键只能有一个
  声明者（fork `packages/client/ui-slots/src/index.ts:1263` 起）：第二个声明者
  `register` 抛「already declared」，该 entry 的 apply 随即失败，
  `assertEntriesActive` 再把它升级为整个 web boot 失败（实测页面停在「Failed to
  load plugins」，控制台只有 `@deepseek-ai/dsh-client-ui-deliverables: failed`）。
  1.0.9 的「共享名字 + `rendersExistingChildren` 兜底」只保护第二个声明者，而归属
  先到先得——本插件先注册即持有该键、后注册的原生卡必抛，实测顺序正好落在兜底覆盖
  不到的一侧，于是整页起不来。本版改为自有键
  `dsh-file-review-kcoder.file.actions`：自己先到就自己声明渲染面，upstream 的键
  留给 upstream 的卡片；本插件的贡献控件仍挂在卡片上，upstream 原生的
  open-with / reveal 控件留在它自己的卡片上，两边互不侵占，启动不再依赖客户端
  激活顺序。
- **不再使用 `rendersExistingChildren`**：该开关保留给 fork `ui-plugin-manager`
  的 Settings 共享宿主，本插件不依赖它。
- **`dsh.client.inject` 纠偏**：去掉已消亡的 `@deepseek-ai/dsh-client-runtime`
  （末版 `0.1.1-rc.2`），改列真实提供方行 `dsh-api-remotes`、
  `dsh-api-session-controller`、`dsh-client-connection`、`dsh-client-locale`、
  `dsh-client-ui-conversation`、`dsh-client-ui-renderer`（`dsh-coding-sidebar`
  保留）。
- **冒烟补回归面**：断言注册键绝不为 upstream 键、且不携带
  `rendersExistingChildren`；render 冒烟断言逐文件渲染走的是自有键。

## 验证

- 测试：smoke 65 → **66**、render 24 → **25**（新增「注册键不为 upstream 键」
  「不携带 `rendersExistingChildren`」「自有键逐文件渲染」）；
- dev home 实机（`~/.kcoder-dev`，0.1.7-alpha.1 引擎 + KCoder 产品 overlay）：启动
  零失败条目、控制台无 error，coding-sidebar 与 file-review 客户端半均正常引导；
- 门禁：typecheck 0 错、build、smoke 66/66 + render 25/25 全绿；幂等复建与提交产物
  等价（仅 CSS module 键序差异，无行为变化）。

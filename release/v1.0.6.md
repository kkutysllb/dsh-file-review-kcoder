# dsh-file-review-kcoder 1.0.6

> 原生侧边栏评审开法接管：`changes-review` 地址改开自家 file-review 页签。

## 背景

上游 ui-deliverables 的改动卡把评审手势发给**原生**右栏
（`ctx.sidebarRight.openResource` + `changesReviewAddress`
= `dsh-resource://changes-review/session/<id>/<seq>/<turn>`），而
dsh-coding-sidebar 的文件打开门只认 `dsh-resource://file/…` 家族、其余
地址一律放行 → 落回原生右栏。KCoder 产品侧压制了原生外壳（产品铁律 1，
docs/ARCHITECTURE.md §12），于是表现为**一片空白**（2026-09-19 现场，
v0.6.14 首发因此撤回）。

评审地址点名的内容——单个 turn 的改动文件审查——本来就是本插件
`file-review` 页签渲染的东西，因此在本插件内认领该地址家族并改道：
认领放在插件（而非宿主）里，守住「上游版本适配随插件发线」的边界。

## 变更

- **新增 `src/client/review-address.ts`**（依赖无关、可独立测试）：
  地址解析（前缀含 session scope；段数/空 id/非数字/坏转义一律
  decline，不猜测不劫持）+ `wrapChangesReviewOpen`（认领改道、其余
  地址原样透传、dispose 还原原方法，HMR/停用不留劫持）；
- **`index.tsx`**：`ctx.inject(['sidebarRight'])` 延迟装配（单次
  `ctx.get` 探针可能先于提供方执行而永久装不上，与 coding-sidebar 的
  门同款）+ `openReviewInSidebar`：按地址里的 session 定 scope，
  paths 取「自有 Definition 优先、timeline derive 兜底」，开/聚焦
  自家 file-review 页签；
- **安装期诊断一行**：`[dsh-file-review-tab] native-sidebar takeover:
  changes-review → file-review tab`（现场排查「点卡片出原生空白」
  只看它）。

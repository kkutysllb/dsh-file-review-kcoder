# dsh-file-review-kcoder 1.0.1

## 新增

- **非代码产物预览**：审查面板此前只覆盖可 diff 的文本变更；现在图片 / 音视频 / Office / PDF / 文档类产出以类型徽标（图片 / 视频 / 音频 / Office / PDF / 文档）呈现，点击走 dsh-coding-sidebar 的文件查看器管线预览（`betterSidebar.openFile` → editor tab → `matchFileViewer`：image / pdf / markdown / html 内置，office / video 查看器插件懒加载；无侧栏时降级为宿主 OS 默认应用打开）。轮尾卡片与侧栏 Tab 两侧一致；artifact 行不参与 undo/巡检，避免假失败提示。
- **bash 产物捕获**：图片等二进制产物通常经终端产生、不在 write/edit 词汇内。`fileReviewChanges` Definition 与窗口派生新增保守捕获：仅限已知产物扩展名 + 明确输出语法（重定向 `>`/`>>`、`curl -o`/`--output`、`wget -O`、`cp`/`mv` 末位参数、`tee`），普通代码命令零误报。

## 修复

- **「另有 N 个文件」不可点击**：轮尾卡片超出 6 行时的折叠提示原本是纯文本 div，无法交互。现改为真正的展开/收起按钮——点击在卡片内展开完整文件列表（`aria-expanded` 标注状态，文案切换为「收起」/「Show less」），默认仍保持 6 行紧凑形态；补齐 hover/focus-visible 反馈。
- **撤销按钮闪烁**：agent 继续执行任务时，历史轮次的「已编辑 N 个文件」卡片上撤销按钮不停闪烁（disabled 态 opacity .45 ↔ 1 往复）。双重根因：
  1. 卡片经 `useSyncExternalStore` 订阅的是**会话级**聊天快照源，agent 执行期间每次流式事件都更换快照引用 → 每张已挂载卡片不停重渲染；
  2. 卡片的宿主状态巡检 effect 以派生数组**身份**为依赖 → 每次快照发布都重跑，`statusPending` true → status RPC → false 往复翻转。
- 修复一（订阅面）：`changesStore` 新增 `getTurnSnapshot(turn)`，卡片订阅值改为 **turn 级内容指纹**（`turnChangesFingerprint`：own Definition 数据签名 + 内置 deliverables 回退签名）。本 turn 内容不动，快照引用怎么换都不再触发本卡片；其他 turn 的变动也彼此隔离。无 timeline 的旧载体回退为窗口形状计数（可过触发、不漏触发）。
- 修复二（巡检面）：巡检 effect 改为**内容键门控 + 300ms 尾沿防抖**（`inspectionKey`：路径#hunk 数；与侧栏 Tab `FileReviewTab` 的 flatKey 方案对齐）。派生数组身份抖动不再发起 status RPC——顺带消除了流式期间的 RPC 风暴与重复派生；同一内容只巡检一次（以巡检器身份 + 内容键为戳），输入为空时立即落定。

## 变更

- `lib/client.js` 追加纯函数导出 `turnChangesFingerprint` / `inspectionKey` / `classifyPath` / `captureArtifacts`（供产物级回归校验，向后兼容）。
- 新增文案键 `produced.collapse`（zh「收起」/ en「Show less」），随展开/收起切换。
- README 安装章节改为 npm registry / GitHub 直装两种方式（`dsh plugin --profile web add`），与本仓 npm 发线对齐。

## 兼容性
